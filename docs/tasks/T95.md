# T95 Reject forged saved campaign histories

- **Kind**: fix · **Issue**: #204 · **Branch**: `task/T95-saved-history` · **Merge after**: T94 10db6ff (post-merge CI 44642046313 passed).
- **Evidence**: [confirmed:#204 probe at 10db6ff] `Campaign::replace_from_bytes` loads
  states the result/week APIs cannot produce: a second-result score changed from the
  witnessed `[1, 1]` that then completes the week, edited post-Sevilla conditions, a
  first result ordered after the second, a week-one state with no first result, and a
  week-two state whose revision omits the week transaction. [confirmed:archaeology
  788b833 T93] The week-2 context already binds the witnessed conditions, cash and
  following fixture; only the score and the history chain are unbound.
- **Owns**: `campaign/src/lib.rs` and `campaign/src/result.rs` validation,
  `campaign/tests/saved_history.rs`, `records/T95/**`, the task's documentation.
- **Scope**: [designed] make decode-time validation bind the history the public APIs
  produce. (1) A recorded Sevilla result must carry the witnessed `[1, 1]` score; (2) a
  campaign holding it must carry the witnessed 18 conditions in both week one and week
  two; (3) the first result's `request_revision` must precede the second's; (4) a
  week-one context must hold the first result that its completion required; (5) a
  week-two context must have advanced the revision past the second result by the week
  transaction's increment. Edits before the first match, edits between the matches and
  higher revisions stay legal: bind lower bounds, never equality of the revision or of
  the whole campaign. This is save validation, not file authentication. Out of scope:
  new match, week or edit behaviour; the first friendly's computed score; captures.
- **Milestones**: frozen task; red-first test file and `records/T95/fail-before-r0001.json`;
  validation fix; full suites, fmt and original-byte check; exact-head CI; pinned squash.
  Use a separate fix worktree; checkpoint at each milestone.
- **Done when**:
  1. `CARGO_BUILD_JOBS=4 cargo test --manifest-path campaign/Cargo.toml --locked --test saved_history`
     fails before the fix and then passes: each of the five forged images is refused by
     `validate()` and by `replace_from_bytes` leaving the live campaign unchanged, while
     a legitimate history with edits before and between the matches, and a revision
     raised above the bound, is accepted.
  2. `CARGO_BUILD_JOBS=4 cargo test --manifest-path campaign/Cargo.toml --locked` and
     `CARGO_BUILD_JOBS=4 cargo test --manifest-path desktop/faithful/Cargo.toml --release --locked`
     pass unchanged, showing no legitimate route or reload regressed.
  3. `cargo fmt --check` in both crates, the original-byte check and exact-head CI pass
     before a pinned PR merge.
- **Hazards**: binding equality instead of bounds rejects legitimate edited histories;
  validating only in `match_ticket`/`record_*` leaves the decode path open, so change
  `validate()` itself. Host-wide ps/free before builds, no build during a capture, one
  Rust build at a time with `CARGO_BUILD_JOBS=4`.
