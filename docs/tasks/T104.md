# T104 The league table model and the two-point rule

- **Kind**: slice · **Issue**: #206 · **Branch**: `task/T104-league-table` · **Merge after**: T95 6d92e2f.
- **Evidence**: [confirmed:archaeology T103 17cf78c] the preparation machine
  stores one 12-byte row per club (`P, PTS, HW, AW, HD, AD, HL, AL, F, A`) and
  applying the eight captured round-28 results to the decoded pre-round rows
  reproduces all 16 captured post-round rows exactly under two points for a win
  and one for a draw. [confirmed:archaeology T102 472badb] the same capture shows
  the results screen, the table screen and the cash flow (in 726,972, out 80,639,
  funds 1,045,060 -> 1,691,393).
- **Owns**: `campaign/fixtures/league-table.json`, `campaign/src/league_table.rs`,
  `campaign/tests/league_table.rs`, the task's documentation.
- **Scope**: [designed] add the league-table data model and the points rule to
  the campaign crate as a self-contained slice: typed rows, the captured round's
  eight results with their scorelines, `apply_round` awarding two points for a
  win, one for a draw and none for a loss while accumulating goals for/against
  and the home/away W-D-L columns, and a validation that the applied round equals
  the captured post-round rows. Carry the captured rows in a committed fixture;
  do not embed original bytes. No campaign schema change, no persistence, no
  match or week transaction yet - those are the next slice - and no ranking
  tie-break claim.
- **Milestones**: frozen task; fixture and model; red-first test; implementation;
  exact-head CI; pinned squash.
- **Done when**:
  1. `CARGO_BUILD_JOBS=4 cargo test --manifest-path campaign/Cargo.toml --locked --test league_table`
     fails before the module exists and then passes: the eight captured results
     applied to the 16 pre-round rows equal the captured post-round rows, a win
     adds 2, a draw 1 and a loss 0, and a deliberate three-point rule is refused.
  2. The full campaign suite and `cargo fmt --check` pass, and no existing test
     or record changes.
- **Hazards**: the captured table is a late-season state (28 played) with 16
  clubs, so do not generalise the row count or the club order; keep the
  home/away column interleaving the original stores. Host-wide ps/free before
  builds, one Rust build at a time with `CARGO_BUILD_JOBS=4`, no capture running.
