# T48 Browser and packaged desktop delivery comparison

- **Kind**: design spike
- **Issues**: #105, parent #103 · **Branch**: `task/T48-ui-delivery-spike` · **Merge after**: T47 and accepted research milestone135.
- **Evidence**: Research `6aca98caeebc1b9b5410852139fa305462224a05`, `docs/manual/native-gaps.md`, supplies seven UI decision requirements and B1–B6. Owner-run review PASS verifies those requirements. Native `a634fb27a2d438c67d20e95cf66aa11bc0737732` provides the accepted watched exhibition, not campaign state.
- **Owns**: `web/spike/**`, `desktop/spike/**`, `tools/smoke_ui_spike.mjs`, `docs/ui-delivery.md`, `records/T48/**`, README spike instructions and generated-dependency ignore rules.
- **Scope**: Compare local-browser delivery and an Electron packaged desktop wrapper using the same disposable HTML/CSS/JavaScript squad workflow. Use clearly designed synthetic players and a versioned spike-only save format. Exercise dense list/detail navigation, preview/commit/cancel of a move, real file save/load, malformed/version-mismatched rejection without state replacement, and offline reopening. Display the existing watched exhibition separately with an explicit boundary: the edited squad does not feed its fixed admitted lineups and its result does not mutate a campaign. Package and launch a Linux desktop directory, record reproducible versions/size and browser/desktop interaction evidence, and document accessibility, distribution and Rust integration tradeoffs. Do not select the final stack or implement original management rules.
- **Milestones**: requirements and acceptance scenarios; shared browser spike; desktop package and equivalent scenarios; measured comparison for owner decision. Commit sources before evidence measurement and preserve unsuccessful attempts with new records.
- **Done when**:
  1. Automated browser and packaged-desktop scenarios verify keyboard selection/detail identity, move cancellation/commit, exported-file reload, invalid-load atomicity and offline restart; new behavior has retained pre-implementation failure evidence.
  2. Comparison maps all seven accepted requirement rows to observed results or explicit untested limitations, records exact source/runtime/package identities and provides run commands plus screenshots. Existing watched view is demonstrated without claiming edited-XI/campaign integration.
  3. Original-file/diff/preservation checks and exact-head hosted CI pass before pinned native squash merge. Owner technology approval remains a separate gate; immutable prior records and engine sources stay unchanged.
- **Hazards**: A shared frontend alone does not demonstrate packaging. Synthetic editor state is not original-game engine fidelity. Linux results do not establish Windows distribution or screen-reader usability.
